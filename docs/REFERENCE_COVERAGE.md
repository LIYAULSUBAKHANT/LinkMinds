## 3. Four Inferred Screens — Visual Gap Documentation

As verified during PDF extraction and explicitly noted in the specifications, **4 screens do not possess a dedicated screenshot in `UI.pdf`**:

1. **Page 07: Institution Registration (`/institution/registration`)**  
   - *Reason:* UI.pdf transitions directly from Page 06 (Role Selection) to Page 08 (Institution Dashboard).
   - *Inferred Architecture:* Multi-step wizard matching the navy-blue/white card architecture, incorporating form inputs for AICTE Permanent ID, institute accreditation, authorised officer credentials, and document attachment placeholders.
2. **Page 13: TEIE Enrolment Timeline (`/institution/students/:studentId/timeline`)**  
   - *Reason:* The PDF explicitly states: *"TEIE Enrolment Timeline (planned screen; design reference pending)"*.
   - *Inferred Architecture:* Horizontal and vertical chronological event stream visualizing student enrolment episodes, transfers, withdrawals, and policy exception flags using the color-coded badge system.
3. **Page 14: APAAR Identity Resolution (`/institution/identity`)**  
   - *Reason:* Detailed functional rules provided in Section 4.E and Proposed Solution PDF, but dedicated mock was omitted from the screenshot gallery.
   - *Inferred Architecture:* Twin-panel resolver featuring structural Luhn validation, probabilistic candidate matching scores (Name, DOB, Gender), exception handling for foreign nationals, and simulated adapter status.
4. **Page 29: Notifications, User Management & Settings (`/admin/notifications`)**  
   - *Reason:* Specification Page 21 explicitly mandates: *"IMPORTANT: Page 29 must not create a second independent User Management module. Page 27 is the primary location for user creation, editing and role administration. Page 29 may provide shortcuts to user administration."*
   - *Inferred Architecture:* Focused on notifications center, notification preferences, alert rules/threshold sliders, and notification templates, with a prominent navigational link to Page 27.
